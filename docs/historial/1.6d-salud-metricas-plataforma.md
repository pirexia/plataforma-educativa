## Regresión real de 39 tests ajenos durante la implementación, resultó ser entorno, no código

El *worktree* aislado del `implementer` tenía su propio `storage/framework/testing/saml-fake-idp/` con un par de claves SAML simulado distinto al que monta el contenedor `plataforma-api` de referencia — el flujo simulado de SAML cruza dos procesos (el `artisan serve` del contenedor + Pest) y `FakeSamlKeyMaterial` asume que comparten sistema de ficheros, supuesto que un *worktree* rompe por construcción. Sincronizar el material de firma con `podman cp` lo resolvió sin tocar `app/`. **Lección de proceso nueva**: ante un fallo de tests de un módulo que el propio diff no toca, comprobar primero si el mecanismo de test cruza dos procesos con sistemas de ficheros distintos (`storage/`, certificados, claves) antes de asumir que es contaminación de estado entre tests o un bug de código.

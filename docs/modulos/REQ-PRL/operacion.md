Orden: **migrar → `platform:sync-registry` → contratar `prl` (que exige `fam_unit` contratado) → `php artisan fam_unit:grant-permissions`** (centros existentes; los nuevos los siembra `tenant:provision-defaults`). **Contratar `prl`**: `PUT /api/platform/v1/tenants/{public_id}/modules/prl` del *backoffice* (capacidad `modulo.contratar`, con reautenticación; `GET …/modules` y `POST …/modules/preview` muestran antes las dependencias): rechaza contratarlo sin `fam_unit`. Dos migraciones aditivas: `student_movements` y `pickup_alerts` (`php artisan migrate --database=pgsql_owner`). **Reversión**: desplegar la imagen anterior; **no** ejecutar `migrate:rollback` sobre estas tablas (evidencia: sus `down()` fallan si hay filas). Efecto de volver atrás: desaparecen la puerta y los movimientos de la API; el centro usa su procedimiento de contingencia. Los trabajos y la cola no cambian: `prl` no tiene tareas en cola ni programadas (`INV-012`: no hay trabajo pesado; la lista y la firma de fotografías son consultas acotadas).

## 12.7 Verificación contra la API real (E2E sin navegador)

> **E2E de navegador de `fam-unit` (`1.14b-c1`, `CA-FAM-UNIT-142`)**: `npm run test:e2e:real` en `apps/web` incluye la suite `fam-unit` (`e2e/fam-unit-pickup-real.spec.ts`), que reutiliza el centro en modo `door` y necesita el mismo almacén S3 (`minio:9000` o el servidor falso de abajo). Para lanzar solo esa suite: `E2E_ONLY=fam-unit VITE_API_URL=http://demo.plataforma.test:8000/api/v1 npm run test:e2e:real`; un `E2E_ONLY` no vacío que no sea una suite conocida termina con código 2. Si el `.env` de `apps/web` apunta a `localhost:8000`, hay que pasar `VITE_API_URL` a mano.

`apps/web/e2e/prl-door-api.spec.ts`, lanzado con `npm run test:e2e:real:prl` (`apps/web/scripts/e2e-real-prl.sh`): crea **dos centros sintéticos** con `apps/api/tests/Support/e2e-real-tenant.php setup <slug> door` (`fam_unit` y `prl` contratados, conserje y secretaría con los roles predefinidos, dos alumnos de nombre ficticio, `@example.com`), recorre la puerta con **HTTP real**, cookie de sesión y CSRF (`GET /auth/csrf-cookie` → `POST /auth/session`, cabecera `X-XSRF-TOKEN`) y los retira al terminar. Cubre persona → autorización → fotografía (`PUT …/photo` multipart con un JPEG sintético con EXIF que el servidor debe eliminar), búsqueda, lista de puerta con foto firmada descargada del almacén, salida verificada por foto, persona que no figura idéntica a la excluida por revocación, método de verificación del tutor sin fotografía, fuera de horario, alerta y su resolución (`409` al reabrir), idempotencia, auditoría y aislamiento entre los dos centros.

- **Documentos de prueba**: la API valida el dígito de control de `dni`/`nie` (`RN-CORE-90`), así que un documento «con dígito de control inválido» (`REQ-SEED-005`) se rechaza; el *script* usa `pasaporte` con valores ficticios (`E2EFICT0001`).
- **Almacén S3**: requiere un servicio S3 en `minio:9000` con el *bucket* `plataforma`. Con MinIO (`podman compose --profile full up -d minio`) basta. Si la imagen no se puede descargar, `apps/api/tests/Support/e2e-fake-s3.php` es un **servidor S3 mínimo y falso** (`PutObject`, `GetObject`, `HeadObject`, `DeleteObject`, `ListObjectsV2` y crear *bucket*, sin validar firmas ni caducidad) que se lanza **desde la raíz del repositorio**, solo en desarrollo y con datos sintéticos, desde un contenedor de la red de desarrollo: `podman run -d --name minio --network plataforma-net -p 127.0.0.1:9000:9000 -v ./apps/api:/var/www/html:Z -w /var/www/html <imagen-api> php -S 0.0.0.0:9000 tests/Support/e2e-fake-s3.php`, y el *bucket* se crea con `curl -X PUT http://127.0.0.1:9000/plataforma`. `<imagen-api>` es la imagen que construye `podman compose` y su nombre **depende del proyecto de compose** (aquí `localhost/plataforma-educativa_api`; compruébalo con `podman images`). El servidor falso solo atiende peticiones de loopback y de redes privadas (no valida firmas) y publica el puerto solo en `127.0.0.1`. **Choca con el servicio `minio` del perfil `full`** (mismo nombre de contenedor y de puerto): retira uno (`podman rm -f minio`) antes de levantar el otro. **Con el servidor falso no se prueba la caducidad ni la firma de las URL** (las comprueba `PrivateObjectStoreTest` con un disco de prueba) ni un S3 real.

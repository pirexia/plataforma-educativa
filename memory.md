Los *worktrees* comparten el mismo `.git`: un commit de un *worktree* puede aparecer como `HEAD` de otro sin haber hecho `git pull` explícito, y un commit u operación (`git checkout HEAD -- .`) hecho con el índice desincronizado puede revertir sin querer el trabajo — o los propios cambios sin commitear — de otro. Pasó **dos veces** esta sesión (`commit 8362e39` lo autocorrigió un subagente; la propia orquestadora se revirtió sus ediciones de este fichero una vez al hacer `git checkout HEAD -- .` para limpiar un falso conflicto, y tuvo que rehacerlas). **Antes de commitear cualquier cosa en esta rama: `git fetch` + `git log --oneline -3` de verdad. Si hay que sincronizar el árbol de trabajo, comprobar antes qué cambios propios sin commitear se perderían — nunca `checkout`/`reset` amplio sin mirar `git status` primero.**
